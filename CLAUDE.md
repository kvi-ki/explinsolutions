## Architecture

Marketing website for an industrial engineering company (automation and electrical systems). Built with **Next.js App Router**, **React 19**, **TypeScript**, and **Tailwind CSS v4**.

**Package manager:** pnpm. **Path alias:** `@/*` → `./src/*`.

### Routing (App Router)

Pages live in `src/app/`:
- `/` — Home page (banner, services overview, contact form)
- `/servicios` — Services listing (data-driven from `src/data.json`)
- `/proyectos` and `/proyectos/[slug]` — Project portfolio with dynamic routes; slug is generated by `src/utils/slugify.ts`
- `/contacto` — Contact form + map
- `/nuestro-equipo` — Team page
- `/actualidad` — News feed (Curator.io)

Root layout (`src/app/layout.tsx`) wraps all pages with `<Header>` and `<Footer>`.

### Data

- **`src/data.json`** — Services definitions and contact info (email, phone, WhatsApp, address)
- **`src/data/projects.json`** — Project array with image galleries and descriptions

### Components

All UI in `src/components/`. Key patterns:
- `contactForm/` uses EmailJS (`@emailjs/browser`) for client-side email sending — requires env vars `NEXT_PUBLIC_EMAILJS_SERVICE_ID`, `NEXT_PUBLIC_EMAILJS_TEMPLATE_ID`, `NEXT_PUBLIC_EMAILJS_PUBLIC_KEY`
- `postCard/` is reused for both projects and news items
- Animations are wrapped via `src/utils/AnimatedService.tsx` (Framer Motion)
- Images use `<picture>` elements with WebP sources for responsive loading; avoid replacing with `<Image>` from Next.js without verifying responsive behavior

### Styling

Tailwind CSS v4 via PostCSS. Custom theme colors are defined as CSS variables in `src/app/globals.css`:

| Variable | Value | Usage |
|---|---|---|
| `--color-accent` | `#7aba4b` | Brand green |
| `--color-text` | `#4d4e4d` | Body text |
| `--color-gray` | `#696969` | Secondary text |
| `--color-lightGray` | `#f2f4f3` | Backgrounds |

Use `accent`, `text`, `gray`, `lightGray` etc. as Tailwind color names (e.g., `text-accent`, `bg-lightGray`).

### Testing

- **Unit tests** (`tests/unit/`): Jest + React Testing Library, jsdom environment. EmailJS is mocked.
- **E2E tests** (`tests/*.spec.tsx`): Playwright across Chromium, Firefox, and WebKit.

## Coding Practices

### Naming

- Use full, descriptive names — never abbreviate for brevity
  - `error` not `e`, `event` not `evt`, `index` not `i`, `element` not `el`
  - `response` not `res`, `request` not `req`, `parameter` not `param`
- Boolean variables and props should read as questions: `isLoading`, `hasError`, `canSubmit`
- Handler functions should be prefixed with `handle`: `handleClick`, `handleSubmit`
- Event prop names should be prefixed with `on`: `onClick`, `onSubmit`

### Styling

- Use Tailwind classes exclusively for all styling — never mix `className` and `style={{}}`
- If a value is not available as a Tailwind utility, use an arbitrary value: `bg-[#065EA6]`, `max-w-[420px]`, `shadow-[0px_5px_15px_rgba(0,0,0,0.1)]`
- Inline `style` props are forbidden except where Tailwind cannot express the value at all (e.g. dynamic CSS custom properties)

### TypeScript

- Enable strict mode; avoid `any` — use proper types or generics
- Prefer `interface` for object shapes, `type` for unions/intersections
- Use `unknown` instead of `any` when the type is truly unknown
- Leverage TypeScript utility types (`Partial`, `Required`, `Pick`, `Omit`, etc.)
- Co-locate types used by a single file; centralize types shared across features in `types/`

### React

- Use functional components with hooks; no class components
- Keep components small and single-purpose
- Lift state only as high as necessary
- Prefer composition over prop drilling; use context sparingly
- Memoize with `useMemo`/`useCallback` only when there is a measured performance issue

## UI Language

All user-facing text is in **Spanish**. Keep this consistent when adding or editing content.
